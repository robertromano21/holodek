SID COMPOSER UPGRADE (Oct 12 2026), incremental and compatible with the existing system
====================================================================

Same arrangement JSON ({bpm,key,scale,voices:[LEAD,BASS,ARP_OR_DRUMS]}), same renderers, same game flow
(getOrGenerateRoomMusic -> generateSidArrangement -> renderArrangementToWav). Old songs still play.

Files
- retort/sidMusicTheory.js (NEW): the music-theory arranger.
- retort/retortWithUserInput.js: generateSidArrangement now asks the LLM for a short MUSICAL PLAN plus a one-bar
  motif (title, mood, key, mode, bpm, progression, patches, bass/arp style, motif rhythm and contour) and has
  sidMusicTheory arrange it. The old note-by-note composer is kept as generateSidArrangementLegacy.
  Also fixed: the caller passed (roomDescription, monsters, key), but the old function read them as
  (token, context), so the room description never reached the prompt.
- assets/renderSid_poke.js (real SID build, used when xa and sidplayfp are installed):
  * every duration now comes from one 16th-note tick unit, so the 3 voices no longer drift out of sync
  * the gate is released 1 frame before each new note (hard-restart style), so repeated notes are re-attacked
  * optional per-voice "pwmSpeed" adds a pulse-width sweep, the classic SID chorus/PWM sound
- retort/renderAudio.js (JS WAV renderer, which this PC uses because xa/sidplayfp are not installed):
  same 20 ms gate gap, PWM sweep, delayed vibrato on held lead notes, a one-pole low-pass for LP/BP-filtered
  voices, and tanh soft-clip mixing.

Music rules
- Mood -> mode: Aeolian epic/sorrow, Dorian noble/Celtic/mystic, Phrygian dread/crypt, Lydian wonder/sacred,
  Mixolydian folk/tavern/march, Major royal/triumph. The tempo bands come from analysing a 1-hour C64 SID
  compilation: about 83-125 BPM is typical, 136-144 is used for battle.
- Progressions: i-VI-III-VII, the Andalusian cadence i-VII-VI-V, i-iv-i-V (harmonic minor), the Phrygian
  i-bII vamp, the Dorian i-IV vamp, I-V-vi-IV, I-IV-V-I, the Mixolydian I-bVII-IV-I, and the Lydian I-II.
- Form: a 12-bar loop. A (4 bars) has the motif, then a sequence, an inversion, and an answer ending on the 5th
  (half cadence). A' (4 bars) repeats it but ends V/IV -> I (authentic cadence). B (4 bars) is higher, busier
  and contrasting, and ends on a dominant/leading tone that turns back to A.
- Melody: notes on the beat and long notes snap to chord tones; passing notes use scale tones. The contour is
  kept when snapping, leaps over a 5th are folded back by an octave, and a breath rest goes in each phrase.
- Bass styles: octave pump, root-fifth with a chromatic or step approach to the next chord, gallop, walking,
  pedal. Arp voice: 16th-note broken triads (up, updown, alberti, broken octave, rolling). It is thinner in
  bars 1-2 for build-up, except in battle and tavern rooms.
- SID patches: hollow/bright PWM pulse leads, bright filtered saw, triangle "flute"; pulse/tri/saw basses;
  glass triangle and chip-pulse arps.
- Validator: keeps the voices exactly 192 sixteenths long so they stay in sync, keeps each voice at 64-192 steps
  (the renderer's limits), and logs metrics (scale ratio, stepwise ratio, leaps).

Uniqueness: the seed is the room coords + description + monsters. The KEY comes from the seed (the LLM always
picked D), and the motif, variations, sequence step, register, patch and style tie-breaks also come from the
seed. The mode, progression and motif come from the LLM's reading of the description, and a motif made of four
plain quarters is replaced. If the LLM fails after 3 tries, the same seeded arranger uses keyword mood
detection, so every room still gets its own tune.

Optional: install xa (xa65) and sidplayfp and put them on PATH to get the real SID chip rendering
(reSIDfp filters) instead of the JS approximation.

SECOND PASS (story, film, reference tunes)
==========================================
The real pipeline, unchanged: the Retort LLM call (retortWithUserInput.js) writes the arrangement JSON. renderSid_poke.js
turns it into 6502 assembly (a player routine plus note tables that write the SID registers $D400-$D418). xa assembles it,
and a PSID header is added to make a real .sid file. sidplayfp (reSIDfp chip emulation) then renders it to WAV. The JS WAV
renderer only runs when xa/sidplayfp are missing (true on this PC: sid\ has the .asm files but no .sid).
- Plan prompt now carries the Children of the Grave story (Mortacia, the lost Sepulchra, Tartarus, Hades, Arithus), film
  film-score lessons and the lament / stately-minor traits. New plan fields: leitmotif, picardy, frameArp.
- Mortacia/Sepulchra leitmotif: tonic, rising 5th, minor-6th sigh, falling back (rhythm long-short-short ... long).
  "main" is used only in Mortacia/Sepulchra/Hades rooms; "quote" opens phrase B in story, underworld and sacred rooms;
  "vary" is a distant echo.
- New moods: underworld (Tartarus), heroic (martial), throne (Hades). Picardy third (major tonic at the A' cadence) for
  throne, sacred and heroic rooms. Phrygian is barred from royal/throne/sacred/tavern/nature rooms.
- New bass styles: lament (stepwise descending line), ostinato_fourth (root/fourth ostinato). New lead contours: triad
  outlines and neighbour-note figures.
- Calm rooms (forest/sacred/mystic/melancholy) use eighth-note broken chords until phrase B (less busy).
- 6502 PLAYER (renderSid_poke.js), all optional and data-driven so old songs assemble the same way:
  * per-frame (50 Hz) chord arpeggios on voice 3: step.chord = [0,3rd,5th]. Chord-shape table plus a cycling routine.
  * noise drum hits on voice 3: step.wave = "NOISE", a per-step waveform override (snare on beats 2 and 4 in battles).
  * delayed vibrato on the lead: the frequency is modulated after 12 frames, depth scaled by pitch.
  * frequency table extended to octave 6 for arpeggio offsets.
  The JS WAV fallback mirrors these features so this PC sounds close to the SID.
- Plan sanity: the LLM's tempo and progression are kept only when they fit the mood, otherwise seeded, which spreads
  songs out across rooms.

THIRD PASS: FULL-LENGTH SONGS (about 2-2.5 minutes before looping), on the true-SID path
=================================================================================
- 6502 player (assets/renderSid_poke.js) is now a tracker-style player. Each voice has an ORDER LIST (up to 254
  entries, FF = loop) of PATTERN numbers. A pattern is 4 bytes per step (frequency index or FF for a rest, ticks,
  arp shape, wave override), ending with FE. Patterns are reached through zero-page pointers ($F7/$F9/$FB), and
  identical patterns are stored once across all voices. This removes the old 64-192 steps-per-voice cap. A 2.5-minute
  song assembles to about 3.5 KB of .sid.
  Old songs (voice.pattern / patternSections) are still accepted: they are split into patterns and played in order.
- Arrangement JSON per voice: "patterns" (one 4/4 bar each) plus "order", in place of the flat "pattern".
- Form (sidMusicTheory.js): intro (bass and arpeggio, then a sparse lead) | A | A' | B | development
  (A var = octave/ornamented lead over new chords, A' var, bridge with an alternate B progression and the leitmotif,
  chant or B var), repeated with different material for faster tempos | B' | A, A' return | coda ending on V, then
  loops to the intro. Length target is about 150 s, with a minimum of 48 bars.
- renderAudio.js renders the WAV to the exact loop length (from the same 50 Hz tick maths as the player), so the
  browser's looping <audio> wraps cleanly. The JS fallback expands the order lists the same way.

FOURTH PASS: ~10-MINUTE MULTI-THEME SUITES
==========================================
- The AI plan now also returns 3 extra themes (danger, reflective, mortacia), each with its own key shift, mode,
  progression, motif and instruments. generateSidArrangement calls SidMusicTheory.arrangeSuite (arrangeFromPlan,
  the single-theme ~2.5 minute song, is still available).
- Suite form (about 10 min, bpm*10/4 bars): Room theme (intro plus full development) -> transition -> Danger (driving
  feel, fast 50 Hz chord arpeggios plus snare that drops out every 4th section, resonant filter sweep on lead and bass)
  -> transition -> Reflection (half feel, pedal/lament bass, triangle counter-melody echoing the lead a bar behind,
  slow filter sweep) -> transition -> Mortacia motif (the leitmotif in a minor mode with a Picardy third) ->
  transition -> Room theme returns -> coda -> loop. Transitions are 2 bars (iv/IV then V of the new key, with a lead
  scale run into the new tonic). Themes are kept on different progressions, and five new progressions were added
  (stately i-iv-VII-III, heroic i-VI-iv-V, Dorian rise, Phrygian march, plagal hymn) to break the AI's
  i-iv-i-V / 104 BPM habit.
- 6502 player (renderSid_poke.js):
  * 16-bit order-list pointers (zero page $F1-$F6), so order lists can hold up to 4000 entries (was 254)
  * a pattern table per voice (up to 255 unique patterns each), with pattern bytes still shared across voices
  * zero-time command steps: $FD AD SR WAVE = instrument change; $FC CUT SWEEP RES|ROUTE = filter
    cutoff/resonance/routing plus a per-frame filter sweep (bounces through the cutoff range)
  * pulse width is initialised on every voice, so a switch to PULSE is never silent
  * PSID subtunes: 1 = the whole song, 2..N start at each movement. Later subtunes start at full volume.
  * a 10-minute suite is about 10 KB of .sid
- renderAudio.js plus the new retort/sidParallelRender.js: long songs are recorded movement by movement in parallel
  sidplayfp processes and joined sample-exactly. On the box a 10:20 song renders in about 17 s instead of 48 s,
  giving a 56 MB 44.1 kHz mono WAV. The JS fallback renders the same song in about 3.5 s (27 MB at 22 kHz).
  No length cap: the WAV length is the exact song length. Earlier 2:00 WAVs were just the old song length.
- Known: the original init code writes the filter cutoff into the wrong registers (low byte to $D415, 3 high bits to
  $D416), so filtered voices sound darker than their nominal cutoff. Left as-is because that is the sound the user
  likes. The new $FC filter commands use correct register semantics.
