# Bounded Local Authoring Reliability

This overlay follows schema-hardening and room-coordination. It is staged only;
the complete parent overlays and matching isolated website engine are required
for a combined test. Do not install it into a busy live engine independently.

| --- | --- | --- |

## Guarantees And Boundaries

Native errors retain finish reason and available token counts. Diagnostics do not
publish reasoning text. Input budget, output exhaustion, empty final content,
schema rejection and semantic rejection remain separate failure classes.
All bounded work orders use strict final JSON by default. Original engine
validators remain authoritative. A complete validated result is required before
publication; no missing authored prose, NPC or music is fabricated.

At most two attempts are made for an ordinary part. An output-limited multi-field
part is split; a failing single field remains a visible terminal failure. Nested
schema repairs are bounded, with only invalid leaves reauthored. Cap, repair,
retry and resume counters distinguish recovery from first-pass success.

Scenery checkpoints are bounded, in-memory and bound to run, model, exact room
input, schema and world direction. Puzzle checkpoints live only within that
design attempt sequence. A transport retry can resume accepted pieces; a failed
compiled puzzle invalidates the plan. These are not persistent game saves.

Startup identity covers finalized character, party, roster, server-selected model
and world within the current character review. A new review explicitly clears a
terminal receipt; stale run results and changed identities cannot join it. Repeated
Save does not repeat campaign setup, profiles or economy initialization. Progress
is scoped to that task. A terminal Retort failure is NOT automatically replayed:
safe whole-game failed-stage continuation still requires a durable side-effect
checkpoint. Server restart recovery and cancellation of backend work are not
implemented by the browser wait signal.

## Acceptance Gate

Replays and contract tests are not a clean-room result. Require a fresh holodek-1
room through population, puzzle, music, scenery, art and narration with zero
required-stage fallback/final failure. Record first-pass generation separately
from bounded recovery. Review room identity, clues, NPC coherence and audible
music, not just JSON validity. The existing full-suite failures remain recorded.

The local generation policy has not been enabled for cloud models. Shared startup
and diagnostic changes have offline coverage; cloud transport routing is retained.
Generalize local constraint/chunking lessons only after the native acceptance gate
and a separately reviewed cross-model evaluation. No paid inference is needed for
the present stage.
