# Room Build Reliability and Local Keys

Background rooms own their destination coordinates. Divine visits, missions,
quest-cast installation and shared spell adoption happen only on real entry.
Prepared rooms retain authored content without changing visited rooms or peers.
Foreign inventory/state writes still fail closed; conflicts are not discarded
as harmless normalization.

Repeated OpenAI enum schemas are shared through `$defs` without changing the
logical contract. The captured puzzle schema drops from 1,999 to 494 enum values.
Provider errors retain safe status/code/field evidence. Permanent schema, access
and quota failures do not become repeated authoring correction prompts; transient
provider failures use bounded backoff. No other model is silently substituted.

New SID development preserves authored contour peaks when choosing chord tones.
Truly narrow realized contours remain invalid, with targeted contour repair.
Previously archived arrangements keep their existing behavior.

## Keys and Private Connections

On the next startup model selection, a paid provider without a remembered key
prompts for masked entry. OpenAI uses `keys/openai.key`; xAI uses `keys/xai.key`.
These files load automatically on later server starts and stay outside Git.
An active environment key keeps priority even when a key is remembered for later.
Only the model ID, not its key, is kept in browser storage.

Provider keys are accepted only from the local matching-origin game window.
Website connection controls are local-only, with pinned SSH host verification.
Connection identities/settings remain under ignored `.retort-data/website-ai/`.
Website jobs receive provider credentials through SSH memory, not saved config.
Diagnostic output redacts credentials and configured deployment identifiers.

All three helper engine hashes must match the PC before room work is dispatched.
The test copy must use the same release without overwriting its private settings,
save files, port configuration or uncapped incognito playtest harness.

## Verification Boundary

Offline regressions exercise the captured five-neighbor ownership failure,
provider-schema transport, targeted SID repair and masked local-key workflow.
They are not evidence of a clean native Luna game run. Live Luna verification
requires the user's own OpenAI key; xAI credentials must never be substituted.
