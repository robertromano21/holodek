# Modular Puzzles And Shrine Art

## Implemented Toolbox

The design pass produces one validated definition, used for both the room's puzzle prose and its actual controls. There are seven mechanical families: ordered buttons, three-position dials, sluice levers, linked levers, tracked sliding blocks, reusable counterweights, and ordered chimes. Fifteen themed kits choose an appropriate receiver instead of always building a cabinet.

There are 24 compatible family/kit pairings, four arrangements, five clue treatments and six materials: 2,880 base specification combinations. This is a compositional count, not a claim of 2,880 different reasoning tasks. Orders, goals, linkages, symbols and story discoveries add variations; many can still share a familiar solution strategy.

Ordinary actions remain deterministic server transactions, with no model call. Every installed control and reference plaque must be reachable. Linked-lever goals are checked for reachability before construction; other families have finite, resettable states. Completion still uses the existing verified XP/quest pipeline, with rewards recorded once. Lore can point toward an existing objective but cannot invent or complete a quest. Starting-room quest timing is unchanged.

The existing design request now allows 4,200 output tokens for mechanics plus bounded art and document metadata. It does not make a second paid request for decoration. Invalid definitions retry once, then use a validated fallback. Context fields are length-bounded.

Mechanism generation now starts with a seeded required family and compatible kit, excluding the last two known families. The model supplies local names, imagery and story inside that brief; responses that copy a different family/kit are rejected and retried once, then fall back to the same valid brief. All seven families remain available across opening-room seeds. The old fixed West/East Sun-Moon-Wave example was repeatedly copied in the game logs and has been replaced with the room-specific scaffold. Five symbol sets also vary fallback dial imagery. Existing saved mechanisms and quest bindings are not replaced.

## Presentation

Mechanical changes animate on the pause-aware game clock without persisting transient animation state in IndexedDB. Replaced GPU buffers are released. The existing character sprites and protected command parser are unchanged.

Sculptures combine pose, head, robe, held attribute and creature form. Deity depictions use a compact visual index of the campaign prompt: Mortacia is the tall blonde White Lady with skeletal dragon wings; the other deities retain their draconic origin. Fresco figures reuse the detailed procedural character generator, with separate pigment treatment. Copies are used so preset character data is not changed.

Fresco design now has independent traditions, subjects and articulated figures. Ten visual traditions are available: Renaissance, classical Roman, classical Greek, medieval Gothic, medieval illumination, Byzantine, Egyptian, Mesopotamian, Romanesque and Baroque. These are stylized fantasy adaptations of framing, depth, ornament, profile/frontal arrangements and scale, not museum reproductions or claims of archaeological accuracy. Historical techniques do not import their religions into the campaign.

Sixteen depicted scene families cover the original ancestral courts, burial rites, dragon wars, scholars, star maps, forges, river crossings, gardens of souls, gatekeepers and pilgrimages, plus oath ceremonies, healers, harvests, storm voyages, dragon flight and lamented cities. Up to six figures can independently choose eighteen poses, three facings, five garment forms, five head treatments (or class-derived costume) and twenty-nine held attributes. The new painter reassembles head, arm, hand and lower-body pixel layers exported through an optional character-rendering metadata path. Ordinary character raster output is unchanged, the original cached parts are copied, and held painted objects grant no real inventory or magic. Artwork is stored as explicit metadata; the LLM chooses from the validated toolbox during the existing design request, not through additional paid image calls.

The additive serpentine dragon recipe has a long curved neck, tapering tail, small angular head, shoulder wings and two digitigrade hind legs, with no separate forearms. Heraldic weapons may appear beside it. The classic dragon recipe remains available. Classical proportions shrink the painted head without changing live sprites or forcing dwarves and fey into human stature. The new statue workmanship path uses a jointed anatomical scaffold, contrapposto, defined faces, fingers and folds rather than the original broad primitives. New statues use a bounded 40-cubed voxel grid and matching isometric map sprites; the classic path and saved metadata remain valid. These are still stylized voxel sculptures, not photorealistic museum replicas.

All 23 campaign deities have canonical composite emblems and favored-weapon motifs, reconciled with the supplied pantheon text. Mortacia's emblem is the winged White Lady, not a generic skull; Rama's is a flaming heart, not a generic sun. Alternate phoenix, unicorn and turtle emblems do not replace those gods' draconic bodies. Painted draconic effigies also vary build, horn, wing, tail and surface treatments; these are art-direction interpretations of the portfolios, not new campaign anatomy facts or live character changes. Silver and blue moon disks intentionally share geometry but use different pigments. Emblems appear in mural medallions, decorative reliefs, altar fronts and statue plinths. Puzzle-control marks and their verified diagrams retain the separate puzzle glyph library, so a similarly named decorative symbol cannot corrupt a clue.

Depicted figures and statues accept bounded race, className, patron and sex metadata. Nine core races and eleven starting classes mirror the game's existing tables. Nineteen additional creature races and sixteen lore occupations are available for underworld processions, guilds, shrines and histories, including scribes, healers, pilgrims, messengers, boatmen, mourners, smiths and standard bearers. Class costumes and painted tools use the existing character assembler; race anatomy, dwarf/halfling/fey stature and elf proportions are preserved. A mortal knight of Atinus remains a knight, not a misidentified draconic god. Raakshasa anatomy is not defined by the campaign prompt, so the current humanoid interpretation is retained rather than importing a tiger-headed mythology. Patron defaults are iconographic composition choices, not gameplay allegiance. Canonical deity bodies cannot be overridden with mortal race/class metadata. Default paintings use local race/class references and patron-related figures when authored art omits them. No new religion, character stats, inventory item or encounter is created by a depiction.

Frescoes layer perspective architecture, grouped figures, planetary imagery and aged pigment. Their compositions include procession, apotheosis, judgment, lamentation, constellation and cosmogony. Painted pigments are independent of the masonry palette: vermilion, lapis, verdigris and ochre preserve contrast, with room lighting still applied in 3D. Missing authored subjects use the established patron and departed figures, not an arbitrary cartoon creature pair.

Up to six authored artworks, four supplementary architectural ornaments and one permanent mechanism diagram can be placed. Indoor buildings normally request four decorative pieces; palaces, basilicas and cathedrals request six. Common interior stonework supplements these with three matching carved wall bands and patterned entrance paving. Bands use coherent dado, skirting or cornice heights, finished end pieces and repeated proportioned centers, retaining all fourteen patterns. Stone colors are sampled from the room's actual backing wall/floor texture, with mortar and decal extremes excluded; recessed and raised details use tonal contrast rather than an unrelated gold palette. Paving occupies only reachable, level, unreserved floor cells without changing collision or navigation.

New mural compositions default to 2:1; 5:2 panoramas and the original 3:2 templates remain available. Background architecture expands and figures are spaced farther apart, while each figure's drawing scale stays uniform. Saved murals fit their natural image ratio inside their existing mounting footprint without rewriting saved geometry. Frescoes span continuous wall sections up to 7.8 tiles wide; height is derived from the chosen aspect ratio and clearance. Placement checks every wall segment, adjacent reachable floor and overhead clearance, leaves exits untouched, spreads murals among different wall faces, and shrinks to panels in cramped spaces. The clue diagram is placed first and remains near the mechanism rather than being moved to the entrance. No room geometry or loot is changed. Art can be examined locally with a dismissible notice, from either end of a large mural. Mural geometry merges equal-color runs and caps raster area at 16,384 pixels (160x80 for 2:1 and 200x80 for 5:2); classic art and carving modules retain 144x96 rasters.

New wall-art placement also requires a reachable viewing witness with clear sightlines to five points across the image. Wider murals require enough standing-back distance; pillars and bulky props cannot be ignored. Unsafe strips shrink or are skipped instead of deleting architecture. Up to fourteen small bronze-and-wax wall sconces are persisted separately from room cells and use the existing warm, occluded torch-light pass. Candles flank paintings and plaques on valid backing masonry, never cover their images or neighboring art. Older saved sconces are repositioned at render time without rewriting IndexedDB layouts. The lighting anchor is just in front of the artwork, not the bounding-box center on a wall-grid corner that caused the observed blackout. Painted pigments use neutral tone ramps and bounded local illumination instead of long-range pillar fill. Their brackets and gently stretching/swaying flames reuse cached meshes and the existing torch flicker clock, not a new timer or API request.

Byzantine mosaics accept the same canonical figures and poses as frescoes, with gold-ground compositions, lapis accents, staggered grout and independently shaded tesserae. They can occupy a wall mural or floor panel; verified puzzle diagrams remain unchanged. These are still code-generated assets, not imported paintings.

Fourteen stonework patterns are available: acanthus, guilloche, egg-and-dart, vine scrolls, dragon knots, ossuary lattices, rosettes, palmettes, wave chains, winged medallions, runic lintels, heraldic beasts, star vaults and interlace. Five borders combine with incised or raised treatments. Decorative artwork uses a continuous height-map mesh, with meaningful normals and at most 55,296 vertices at the normal raster size; puzzle diagrams retain flat, exact verified glyphs. Inscribed fixtures can carry ornament and canonical deity motifs, with higher-detail front-face engraving. Stored wording and click-to-read behavior remain unchanged. The original simple carving and fresco paths have not been removed.

Instruction plaques add four fictional engraving alphabets (draconic, sepulchral, astral and wedge-like) around the exact verified control marks. Both faces have recessed height-map lettering and beveled rims, bounded at 43,008 vertices per face. This is decorative transliteration, not a historical language or a new mandatory deciphering puzzle: clicking still reads the original clue. Old duplicate object-mounted diagram overlays are replaced by these faces at render time; wall and floor diagrams remain. Object diagrams share the plaque body's room-light selection range so a lit frame cannot surround an artificially black face. No extra paid model/image request is needed.

Altars have horned, stepped, draconic, canopied and carved-backplate forms. Canopies have structural supports. Zero to three candles are allowed per authored shrine; wax and flames have distinct geometry and nearby candlelight participates in the existing warm-light system. Altar puzzle kits use mounted offering tracks or incense controls; they do not yet consume inventory offerings.

Existing saved room layouts and puzzle states are not regenerated. Visual animation works with existing controls. New art assemblies and additional families require newly constructed rooms.

Refined sculptures use a 48-voxel grid, distinct facial planes, separated fingers and draped chest/skirt folds. Local cavity shading retains eye sockets and carved creases under torchlight. Saved statue receivers without an explicit classic-workmanship override get a detached refined visual specification; the stored mechanism definition, ID and completion state are unchanged. The classic sculpture renderer remains available. These remain stylized voxel figures, not photoreal classical sculpture.

## Documents And Inscriptions

The unchanged ordinary loot pass generates 1-5 weapons, shields, armor or Other items. Up to four authored books, spellbooks, scrolls and maps are appended separately, not substituted for combat equipment. They retain ordinary equipped-item modifiers. Their backstories and up to three short chapters are persisted outside the flat object-property lines, with browser room data cached in IndexedDB. Taking a document does not erase its source text; carrying it permits reading it in another room. Existing documents without this metadata keep their original narrative path.

Up to four stone tablets, gravestones, chest tombs, sarcophagi or obelisks can also carry authored inscriptions. These remain solid scenery, not backpack items. They have distinct voxel and map silhouettes, carved emblems, hover labels and click-to-read commands. Obelisks carry vertical emblem registers on all four faces. Reading checks the living player, room, distance and intervening walls. Repeated reads return the same stored text with no model call. Only an explicitly bound clue document or inscription includes the actual verified mechanism diagram; a nearby permanent plaque keeps mandatory puzzles solvable even if a portable clue is left behind.

Spellbooks reserve bounded spell reference IDs for the future magic system. Reading does not consume an item, equip it, teach/cast spells, award XP or open a tomb. Observed document text enters the character memory ledger as attributed reading, not a newly adjudicated campaign event.

## Inspection And Limits

The isolated environment lab includes all seven families and a shrine-art gallery. It does not require paid model requests or modify an active campaign. The browser UI probe tests local art inspection, input locking, existing pickup/drag behavior and subtitles. The GPU probe checks artwork rendering, intermediate poses and buffer disposal. Unit tests traverse reachable wrong states and confirm an available solution.

Not implemented by this pass: unrestricted Sokoban, room-wide flooding, beam tracing, perspective-triggered solutions, inventory synthesis/forging, item exchanges or NPC-distraction puzzles. Those need dedicated state transitions and ownership checks before the model can offer them. No popup puzzle screens have been introduced.
