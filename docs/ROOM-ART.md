# Grave Master Room Art

Each entered room can receive a unique 320x200 pixel illustration with unrestricted Modern-mode colors. The Grave Master chooses a bounded, enum-based component composition using the exact saved room name and description. The description carries the day: a wasteland, graveyard, castle, temple or alien landscape must depict that place, not a stock room template. Room art is descriptive only: it cannot spawn characters, treasures, doors, clues or gameplay changes. There is no image-model or DALL-E dependency.

`retort/roomIllustration.js` handles Retort planning, validation, two-request concurrency, deduplication, stale-campaign/description checks and a 30-second failure cooldown. Only the active room can be requested through `POST /room-illustration`. Generation does not hold the game-command lock. An unavailable provider produces a visible retry state, not a falsely labeled stock illustration.

The validated recipe lives in `roomNameDatabase[geoKey].illustration`, so it travels with saves. An additional content-addressed recipe cache lives in `.retort-data/room-art/` (already gitignored). Missing cache files do not invalidate a saved recipe. Changes to the saved name, description or physical/planar context invalidate old art; combat health, discoveries and room geometry do not. Async publication merges only the art field into the latest room record.

`assets/roomIllustration.js` paints the component layers at native resolution with integer pixels, outlines, texture and perspective. The expanded toolkit includes shaded mountains, layered stippled clouds, dunes, masonry towers, citadels, perspective roads, fluted pillars, pediments, trees, crystal clusters, graves, bridges, pools, fresco panels and mosaics. Arbitrary #RRGGBB pigments and derived shade ramps are retained in the saved recipe; there is no C64 palette restriction on Modern art. Retro Mode alone maps the finished picture to its C64 palette, and switching back restores the unchanged original. The browser rasterizes a recipe once, not on every frame. No lighting or fog is baked into the room painting. `assets/roomArtUi.js` displays it in Game Console and records an illustration on every room entry, including revisits; routine console refreshes do not create duplicate entries. Revisits reuse the existing composition. A first-time illustration may finish after the room appears; it fills the matching log entry without replacing a different room's image. The first visit after loading an older save lazily authors its missing art, without rebuilding the room.

Click a room image in either console or log to open `assets/artViewerUi.js`. Clicking a reachable fresco or mosaic in the 3D scene, including a floor mosaic, opens that same modal viewer. Surface artworks are painted from their existing saved composition and pigments, face-on, without world lighting, fog or camera distortion. This does not regenerate the artwork or change puzzle state. The viewer closes with X or Escape, traps focus through native modal-dialog behavior, and restores the prior control without altering a draft command.

Room construction and cached-room activation also trigger the illustration, using the actual room's saved identity or scene source. This covers startup when the floor arrives before the final character-review/console response. The console reserves an initially empty art slot; it never substitutes the game logo for a missing room painting.

Tests: `node --test tests/room-illustration.test.cjs`; `node tests/run-dungeon-ui-probe.cjs --art-only` (also `--narrow`). Probes use frozen authored fixtures and mocked model responses, not the running campaign or paid API calls.

Save the running adventure before restarting the server and refreshing the browser to activate the new backend and assets. Test runs do not restart the live server or edit live saves.
