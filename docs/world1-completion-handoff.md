# Genre and City Handoff (2026-10-20)

## Source Integration

The opt-in source expansion is integrated into `holodek-1` and its
`../holodek-1-world1-test` copy. Concurrent prompt edits are preserved. Backups and
the before/after MD5 manifests are under `.retort-data/genre-city-backups/` in each
workspace. No service is restarted and no Runpod deployment, downloaded model,
credential or saved game is replaced by this integration.

`CITY_SITES`, `GENRE_EXPANSION`, `ARCHITECTURE_EXPANSION`, `CITY_COMPLETE` and
`TRADE_ROUTES` remain off by default. Existing feature switches retain their
previous values. See [world1-completion.md](world1-completion.md) for test-process
activation and commands. This is not permission to enable the expansion in live.

## Completed Scope

- Eighteen genre kits: twelve existing genres plus gothic-horror, solarpunk,
  dieselpunk, underwater, prehistoric and desert-fantasy.
- 144 additional native genre voxel recipes, eight additional CotG pieces and
  54 wall/floor/door materials; matching clothing in existing 2D and 3D actor paths.
- Shared real catalog across Holodek's picker, architecture choices, native props,
  texture library, procedural room illustrations and sandbox.
- Own-world start geometry, campaign atlas, factions, city placement and authoring
  prompts through `settingLayer`; explicit generation errors, not CotG fallback.
- Collision-safe enterable cities, district roles and population guidance,
  persistent markets, labeled real building destinations and browser-sync protection.
- Bounded market-demand propagation over existing unlocked routes, including
  cavern/surface links; no invented goods, currency, rewards or quest progress.

Existing actors, deaths, recruitment, inventory, puzzles and movement cells are
not regenerated by city metadata upgrades. Previously saved scene geometry is
preserved; new entrance dressing is applied when a scene is built, not by forcibly
rebuilding saved levels. All art remains procedural; no image API is called.

## Verification

Luna remains the default (`gpt-6-luna`); explicit saved/manual model choices still
work. Live generation checks use Luna, never the downloading local model.

- Focused suite: 31/31 (27 genre/city tests and four Luna-default tests), plus two
  updated startup checks for cached CotG and homebrew starts.
- Existing genre runner: 20/20.
- Isolated full suite: 2,299/2,332 after integration, 2,272/2,305 before it;
  identical 33 failing test locations and all 27 new tests passing.
- Native-dialog-approved live smoke test: 12 calls, all to `gpt-6-luna`.
  Western, sci-fi and underwater each produced a valid bible, master prompt,
  playable roster and native level specification without CotG setting leakage.
- Real authoring transport tested offline with a fake streaming SDK response:
  outgoing model is Luna and the builder receives no CotG system header.
- Native procedural contact sheets inspected for buildings, tiles and both actor
  rendering paths. Regenerate with `node tools/preview/world1-completion.cjs`.

The full suite is not green. Before source installation the actual main worktree
reported 54 failures; several VM/source-fingerprint/model-default harnesses already
fail. The final installed run reported 2,305/2,364 with 59 failures in main and
2,309/2,364 with 55 in the test copy.
The five additional main failures name missing `StoryPrompts` in VM harnesses and
follow a concurrent, separately owned Holodek-1 history-recall change; it is retained,
not reverted. Compare against the isolated no-regression result, not a false claim
that either worktree's full suite passes. Exact logs are in each workspace's
`.retort-data/genre-city-*.log` files. New feature flags remain off.

A full browser playthrough is still required before live activation: Mode 4
through the first room, city entry/re-entry, markets, save/reload and both visual
modes. Obtain native-dialog permission before any browser or live-model session.
No commit or push is performed by this work.
